# 持仓明细与批次管理去重设计

## 目标

消除“持仓明细”和“梦想金库账本 / 当前持仓”对当前仓位的重复展示，同时保留管理员处理持仓批次、成本和交易操作的能力。

## 信息架构

### 持仓明细

- 作为全站唯一的公开实时持仓总览。
- 保留代码、名称、持仓数量、持仓市值、持仓占比、成本价、当前价、浮动盈亏和浮动盈亏率。
- 行情来源与板块信息不再通过第二张公开持仓表重复展示；需要时可进入行详情查看。
- 普通访客不显示任何编辑、买入、卖出或批次管理入口。

### 梦想金库账本

- 账本改为可横向滑动的分页区域，首屏显示轻量“账本概览”，不直接铺开交易流水表。
- 普通访客从账本概览向左滑动后进入“交易流水”，只能查看历史记录。
- 原“当前持仓”改名为“持仓批次管理”，并设为仅管理员可见。
- “持仓批次管理”沿用现有持仓和成本数据，不建立第二份数据源。
- 管理员可在此处理批次、成本和持仓相关操作；交易流水、资金流水、备份与恢复保持原有职责。

### 账本概览

- 只展示持仓数量、交易记录数量、最近一次交易和累计已实现盈亏等摘要，不重复逐股持仓数据。
- 页面底部显示分页指示点，并支持触摸滑动、鼠标拖动和左右切换按钮。
- 桌面端和手机端采用相同分页顺序；表格页面允许内部横向滚动，不与整页切换手势冲突。

## 权限与默认状态

- 非管理员：分页顺序为“账本概览、交易流水”，隐藏所有写操作。
- 管理员：分页顺序为“账本概览、交易流水、持仓批次管理、资金流水、备份与恢复”。
- 所有用户进入账本时默认显示“账本概览”。
- 管理员身份切换后，当前页面若无权限，自动回到账本概览。

## 不变范围

- 不修改行情代理、缓存和刷新策略。
- 不修改持仓聚合、平均成本、已实现盈亏和浮动盈亏算法。
- 不修改现有交易、资金和备份数据结构。
- 不修改 GitHub 云端账本同步机制。

## 验收标准

1. 普通桌面端和手机端页面只出现一张当前持仓表。
2. 普通访客无法看到或通过页面入口进入持仓批次管理。
3. 管理员可以看到并使用“持仓批次管理”。
4. 普通访客和管理员进入账本时默认显示账本概览，可横向滑动进入各自有权限的页面。
5. 桌面端支持按钮或鼠标操作，手机端支持触摸滑动，交易表格自身仍可横向查看。
6. 原有持仓数量、成本、市值、盈亏及交易流水内容不因本次调整发生变化。
