# 持仓明细与批次管理去重设计

## 目标

消除“持仓明细”和“梦想金库账本 / 当前持仓”对当前仓位的重复展示，同时保留管理员处理持仓批次、成本和交易操作的能力。

## 信息架构

### 持仓明细

- 作为全站唯一的公开实时持仓总览。
- 保留代码、名称、持仓数量、持仓市值、持仓占比、成本价、当前价、浮动盈亏和浮动盈亏率。
- 行情来源与板块信息不再通过第二张公开持仓表重复展示；需要时可进入行详情查看。
- 普通访客不显示任何编辑、买入、卖出或批次管理入口。

### 梦想金库账本

- 普通访客默认进入“交易流水”，只能查看历史记录。
- 原“当前持仓”改名为“持仓批次管理”，并设为仅管理员可见。
- “持仓批次管理”沿用现有持仓和成本数据，不建立第二份数据源。
- 管理员可在此处理批次、成本和持仓相关操作；交易流水、资金流水、备份与恢复保持原有职责。

## 权限与默认状态

- 非管理员：隐藏“持仓批次管理”“资金流水”“备份与恢复”及所有写操作；账本默认打开“交易流水”。
- 管理员：显示“持仓批次管理”“交易流水”“资金流水”“备份与恢复”；账本仍默认打开“交易流水”，避免重复看到当前持仓。
- 管理员身份切换后，当前标签若无权限，自动回到“交易流水”。

## 不变范围

- 不修改行情代理、缓存和刷新策略。
- 不修改持仓聚合、平均成本、已实现盈亏和浮动盈亏算法。
- 不修改现有交易、资金和备份数据结构。
- 不修改 GitHub 云端账本同步机制。

## 验收标准

1. 普通桌面端和手机端页面只出现一张当前持仓表。
2. 普通访客无法看到或通过页面入口进入持仓批次管理。
3. 管理员可以看到并使用“持仓批次管理”。
4. 普通访客和管理员进入账本时默认显示交易流水。
5. 原有持仓数量、成本、市值、盈亏及交易流水内容不因本次调整发生变化。
