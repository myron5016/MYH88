# V11.7 绿色资产档案舱：视觉系统与持仓地图设计说明

## 1. 目标

V11.7 将梦想金库升级为一套更高级、克制、有科技感的家庭资产仪表盘。

本版本重点处理：

- 统一品牌视觉、字体、颜色和间距令牌。
- 让 Hero、仪表盘主体、持仓地图、收益曲线、账本和收尾页属于同一套设计语言。
- 将持仓地图重构为整宽的资产地形图，提升多持仓下的可读性和稳定性。
- 让 Logo、股票代码、持仓金额和占比根据色块尺寸自动降级显示，不再发生文字溢出或裁切。
- 增加有节奏的入场、状态和悬停动效，同时保证低性能设备和 reduced-motion 用户可用。

## 2. 已确认的产品原则

- 持仓地图面积继续由每只股票的持仓成本占比决定。
- 每只股票仍然是一个色块，不改变数据表达方式，不按板块合并面积。
- 板块只影响颜色家族和图例，不改变单只股票的真实面积。
- 现有行情、TWE/Finnhub fallback、静态缓存、账本、分批成本、定投、收益率曲线和管理员权限逻辑保持不变。
- `data.json`、`backups/`、Worker 配置和持仓数据不作为视觉版本的编辑对象。
- V11.7 继续使用现有静态 HTML/CSS/JS 架构，不进行 React/Vite 迁移。

## 3. 视觉方向：绿色资产档案舱

### 3.1 品牌气质

关键词：家庭档案、长期主义、清醒、可靠、轻科技、可持续。

页面应该像一份被认真保存的家庭资产档案，同时具备投资终端的扫描效率。

### 3.2 色彩令牌

基础色：

- `--brand-canvas`: 温和的近白背景，用于页面底色。
- `--brand-surface`: 白色内容表面，用于主要面板。
- `--brand-surface-soft`: 淡薄荷表面，用于表头、筛选器和辅助区域。
- `--brand-ink`: 深墨绿，用于主标题和重要数字。
- `--brand-muted`: 灰绿色，用于说明、时间和次级信息。
- `--brand-green`: 品牌青绿，用于主按钮、进度、在线状态和导航焦点。
- `--brand-green-deep`: 深森林绿，用于深色 Hero 文字区和高对比按钮。
- `--brand-lime`: 柔和黄绿色，用于品牌细节和少量强调。

语义色：

- 上涨使用珊瑚红，遵循用户习惯。
- 下跌使用翠绿色，遵循用户习惯。
- 中性状态使用深蓝灰或暖金色，不使用与涨跌混淆的品牌绿。

地图色彩：

- 各板块拥有一个基础色家族。
- 同板块股票只改变明度、饱和度和轻微色相，不随机跨色。
- 颜色变化由稳定的股票排序决定，买入或卖出其他股票时不会让所有现有股票大幅换色。
- 色块背景使用轻微光照层，不使用强烈玻璃拟态、霓虹外发光或大面积渐变。

### 3.3 字体与数字

中文优先使用本机无网络字体栈：

`"Noto Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`

数字和股票代码使用稳定的数字排版：

- `font-variant-numeric: tabular-nums`。
- 金额、价格、收益率列禁止因数字长度变化造成横向跳动。
- 标题使用较紧凑但不压缩的字重，不使用过度夸张的字间距。
- 地图标签使用白色高对比文字，必要时加柔和阴影，不再出现白字黑字混用。

## 4. 页面结构

### 4.1 Hero

- 保留宝宝照片作为品牌资产，但增加明确的内容安全区，避免头像和标题互相遮挡。
- 左侧承载品牌标识、主标题、长期目标文案。
- 右侧承载刷新行情、进入持仓和安装按钮。
- 状态信息采用轻量信息带，不堆叠成一排难读的小标签。
- 桌面端使用宽幅封面；手机端使用竖向裁切和两级内容，不强行保留桌面构图。

### 4.2 仪表盘主体

- KPI 卡片统一为同一高度和同一内部节奏。
- 重要金额放在标签下方，状态与时间放入弱化副行。
- 颜色只表达信息状态，不让每张卡片都变成装饰色块。
- 所有功能入口继续使用原有 DOM id 和事件处理函数。

### 4.3 持仓地图

- 地图独占整宽区域，持仓明细放在地图下方，避免同排压缩。
- 地图容器使用稳定的响应式高度，桌面端保持宽阔画布，手机端保持可读纵向画布。
- 色块之间使用清晰的细分隔线，圆角控制在小范围，保留“地图”而不是卡片墙的感觉。
- 持仓成本占比低的股票仍保留真实面积，但标签按尺寸规则降级。

地图标签规则：

1. `large`：Logo、代码、持仓金额、占比全部显示。
2. `medium`：Logo、代码、金额和占比显示，缩短辅助文案。
3. `small`：优先显示 Logo、代码和占比，金额进入 `title` 与可访问标签。
4. `micro`：只显示 Logo 或代码，金额和占比进入 `title`、键盘焦点说明和移动端详情提示。
5. 标签容器必须 `overflow: hidden`，任何文字不能撑大色块或遮住相邻色块。

Logo 规则：

- 优先使用仓库内真实 Logo 资源。
- 新增股票没有本地资源时，使用现有远程 Logo fallback 和代码缩写 fallback。
- Logo 失败时不显示破图图标，不让错误图片占用布局。
- Logo 只作为识别辅助，不替代股票代码和金额信息。

### 4.4 持仓明细

- 作为地图下方的完整数据表，继续保留当前价、成本、持仓价值、占比、浮动盈亏、盈亏率和操作权限。
- 代码列带 Logo，但行高、数字列和操作列固定节奏。
- viewer 模式隐藏管理员操作，管理员模式才显示操作按钮。
- 桌面端优先扫描效率，手机端使用横向滚动或分层摘要，不压缩成不可读的九列表格。

### 4.5 收益曲线、账本与定投

- 继续保留三段收益率曲线、账本、交易流水、定投专区和管理员面板。
- 只统一标题、表头、控件、状态和间距，不改计算口径。
- 个股收益率与定投收益率继续分开显示。

### 4.6 收尾页

- 保留宝宝照片和整屏收尾语句。
- 使用完整人物安全区，避免脸部被裁切成半张脸。
- 文案和按钮放在稳定的暗部内容区，图片主体不承载必须阅读的文字。
- 收尾动效只做轻微缩放和内容上浮，禁止影响阅读和滚动定位。

## 5. 动效系统

### 5.1 动效层级

- 页面首次进入：Hero 图片轻微入场，品牌文字和状态带分层出现。
- 内容进入视口：面板使用 IntersectionObserver 分批出现，避免整页同时跳动。
- 地图渲染：色块按持仓权重顺序错峰出现，持续时间短，避免等待感。
- 悬停和聚焦：单个色块提升对比度，其余色块轻微降权；不改变面积和数据。
- 数据刷新：只让状态点、更新时间和相关按钮反馈，不让整页闪烁。

### 5.2 动效边界

- 不新增 scroll 监听器，继续使用 IntersectionObserver 或 CSS animation。
- `prefers-reduced-motion: reduce` 时关闭位移、缩放和错峰，只保留必要的状态变化。
- 动效不能改变表格列宽、地图尺寸和任何金额布局。
- 动效不能阻塞行情刷新、账本初始化和页面交互。

## 6. 技术实施边界

建议新增：

- `brand-v11.7.css`：新的品牌令牌、页面层级、地图视觉规则、响应式覆盖和动效。
- `brand-v11.7.js`：只负责视觉层的可见性、地图焦点和非阻塞交互，不接管行情和账本状态。
- `tests/brand-v11.7.test.mjs`：锁定视觉入口、地图标签规则和 reduced-motion 合同。

必要时修改：

- `index.html`：替换视觉层资源版本并补充不改变业务行为的语义 class。
- `script.part3.js`：只在需要增加地图尺寸等级、Logo fallback 或可访问属性时做最小改动。
- `service-worker.js`、`build-meta.json`、`package.json`：统一 V11.7 版本与缓存指纹。

禁止修改：

- `data.json` 和 `backups/`。
- 行情代理、TWE/Finnhub fallback、静态缓存和市场时钟逻辑。
- 持仓成本、批次、部分卖出和定投计算逻辑。

## 7. 验收标准

功能与数据：

- 现有测试全部通过，新增视觉合同测试通过。
- 页面加载后仍能读取云端账本、刷新行情、显示缓存、切换收益率曲线和记录定投。
- viewer 模式不能看到或触发买入、卖出、编辑、保存 GitHub 等管理员操作。
- 视觉版本更新不改变 `data.json`、`backups/` 和 Worker 配置。

桌面端：

- 1920x1080、1440x900、1280x800 下无地图越界、无横向滚动条、无文字裁切。
- 地图是整宽主视觉，明细位于地图下方。
- 8、12、20、30 只持仓时地图色块无重叠，标签不会撑破布局。

手机端：

- 390x844 和 430x932 下 Hero、KPI、地图、明细、曲线和底部导航可用。
- 地图保留真实占比，微型持仓可通过 Logo、代码或详情提示识别。
- 不出现桌面端两列内容挤压、按钮溢出和固定宽度导致的横向滚动。

视觉：

- 品牌绿只表达品牌和系统状态，涨跌色语义稳定。
- 同板块色块属于同色系，现有持仓排序变化不会导致全图随机变色。
- 真实 Logo 优先，失败时使用干净的代码 fallback，不出现破图。
- reduced-motion 下页面仍可读、可交互、可定位。

## 8. 非目标

- 不在 V11.7 引入 React/Vite。
- 不重写行情代理和 Worker。
- 不增加 AI 股票分析、期权策略或交易建议功能。
- 不改变当前持仓的成本、数量、交易流水或收益计算。
