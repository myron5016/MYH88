# V11.5 Stability Patch Design

## Goal

Prevent stale fallback quotes and slow startup from producing misleading portfolio values, while preserving the existing ledger schema, manual FX behavior, Twelve/Finnhub routing, holiday handling, and GitHub-backed portfolio data.

## Scope

This patch changes only the frontend quote fallback and initial-load orchestration. It does not modify `data.json`, transactions, positions, price providers, the Worker routing policy, or administrator permissions.

## Design

### 1. Freshness gate for static quote fallback

`kv-quotes-all-current.json` is used only after every configured Worker proxy fails. Before accepting it, the frontend will validate the wrapper timestamp and the quote timestamps. A static quote is acceptable when it is no more than two completed US trading sessions behind the current market calendar. The check must tolerate weekends and listed US holidays.

If the static file is too old or malformed, the fallback fails closed: existing in-memory/local prices remain untouched, the refresh reports that no reliable quote is available, and the UI must not recalculate portfolio P&L from the stale values.

### 2. Non-blocking initial load

After shared ledger data is parsed and rendered, the page will start the market-price refresh immediately in the background. The current-month opening snapshot will also run in the background and may update the return curve when it succeeds, but it cannot block the first render or prevent the normal live/last-close price path from running.

The existing refresh mutex, manual FX mode, market-open decision, last-close mode, and status labels remain unchanged. Failures are caught and reflected in diagnostics instead of replacing the rendered state with zeros.

### 3. Test coverage

Add focused Node tests for:

- fresh static quote acceptance;
- stale static quote rejection;
- weekend/holiday tolerance for the two-session rule;
- malformed static cache rejection;
- startup orchestration proving price refresh is scheduled even when the opening snapshot fails.

The existing full test suite must remain green, and `data.json` must be byte-for-byte unchanged.

## Acceptance Criteria

1. A static cache dated 2026-06-29 is rejected on 2026-08-09.
2. A Friday close remains valid during the following weekend and listed holiday window until two completed sessions have passed.
3. A failed opening-snapshot request does not delay the initial ledger render or prevent price refresh scheduling.
4. No code path turns a stale fallback quote into a new portfolio price or P&L value.
5. `npm test` passes and `data.json` is unchanged.

## Out of Scope

Cloudflare Access authentication, GitHub Actions browser smoke tests, automatic static-cache publishing, and Worker calendar data maintenance will be handled as separate follow-up work after this patch is verified.
