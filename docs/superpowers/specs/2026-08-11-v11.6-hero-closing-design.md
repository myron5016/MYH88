# V11.6 Hero 与收尾页视觉升级设计

## 1. 目标

在不改变梦想金库现有行情、账本、持仓、收益率、定投、管理员和 PWA 逻辑的前提下，升级页面的品牌入口与页面结尾。

本次只实现两个视觉区域：

1. 全屏 Hero 首页，包含宝宝照片、大标题、桌面导航、刷新及安装入口、运行状态。
2. 整屏收尾页，使用第二张宝宝照片完成长期陪伴与未来感的品牌收束。

页面主体功能区保持现状。此次升级的成功标准不是增加功能，而是让进入网站和离开网站时的体验更高级、克制、有家庭温度，并与白绿清新视觉系统一致。

## 2. Design Read

这是一个面向家庭内部使用的个人投资账本。它同时需要金融数据的可信度和父母为孩子长期积累的情感表达。视觉语言采用清新白绿、自然摄影、克制科技细节和有目的的电影式动效，不采用模板化金融大屏、霓虹紫色、深色赛博背景或卡片堆叠式 Hero。

设计参数：

- `DESIGN_VARIANCE: 6`，保持清晰秩序，在摄影裁切和文字构图上适度不对称。
- `MOTION_INTENSITY: 7`，Hero 与收尾页具有明显动效，但数据区保持稳定。
- `VISUAL_DENSITY: 4`，首尾区域留白充足，运行状态集中在单条信息轨道。

## 3. 现状审计

### 3.1 保留内容

- 标题“孟一晗的梦想金库”。
- 副标题“爸爸妈妈为你种下的未来”。
- `refreshButton`、`installAppButton` 及原有 `onclick` 行为。
- `diagnosticsStrip` 内的版本、行情、美股时钟和账本状态 ID。
- `syncStrip`、更新提示和所有后续功能模块。
- 页面现有锚点：`overview`、`allocationMap`、`analytics`、`ledgerPanel`、`dcaZone`。
- 手机端底部导航。
- 当前管理员权限、行情刷新、PWA 安装和服务工作线程逻辑。

### 3.2 需要替换的视觉模式

- 当前 Hero 是普通横向信息卡，缺少全屏品牌体验。
- 头像只作为圆形装饰，不能承载家庭品牌主题。
- 运行状态与品牌标题挤在同一个紧凑面板中，视觉优先级不清晰。
- 当前页尾只有一行文字，无法形成完整的结束体验。
- Hero 样式被多份历史 CSS 同时覆盖。本次新增独立样式文件，并在加载顺序末尾引入，减少继续叠加旧选择器的风险。

## 5. Hero 设计

### 5.1 布局

Hero 是首屏全幅摄影场景，使用 `min-height: calc(100dvh - 20px)`，底部保留极小的下一屏提示边缘。照片铺满区域，不做左右两张卡片式分栏。

顶部为单行导航：

- 左侧品牌标记 `MYH88` 与 `Family Dream Fund`。
- 中部桌面导航：总览、持仓、收益、账本、定投。
- 右侧轻量操作：安装到手机。

主体文案左对齐并放在照片安全区：

- 小标题：`FAMILY DREAM FUND`
- 主标题：`孟一晗的梦想金库`
- 副标题：`爸爸妈妈为你种下的未来`
- 主操作：`进入金库`，滚动到 `syncStrip`。
- 次操作：`智能刷新行情`，复用现有 `refreshButton` 和函数。

文案直接叠加在摄影背景上，不放入独立卡片。左侧使用白色半透明遮罩提升文字对比度，遮罩只服务可读性，不使用玻璃卡。

底部为运行状态轨道，承载现有四项诊断数据。桌面端横向排列，移动端允许水平滑动。状态轨道属于 Hero 的信息收尾，也向用户提示下方是可操作的真实投资应用。

### 5.2 摄影裁切

- 桌面端以宝宝面部位于画面右侧中上区域为基准，标题占左侧约 42% 安全区。
- 1440 x 900 和 1920 x 1080 下不得遮挡眼睛、嘴部和主要苹果枝叶。
- 移动端使用同一原图的独立裁切规则，宝宝面部位于上半区，标题位于下半区白色渐隐区域。
- 使用稳定的 `object-position` 和容器约束，不按视口宽度动态缩放字体。

### 5.3 动效

进入页面时按以下顺序播放：

1. 图片从轻微放大状态缓慢归位，并通过裁切遮罩完成揭幕。
2. 导航淡入并向下移动 8px。
3. 小标题、主标题、副标题和操作按钮依次出现，每项间隔约 80ms。
4. 一条低饱和绿色轨迹从标题区域延伸至状态轨道，表达长期增长，不模拟真实行情。
5. 状态轨道最后进入，确保数据状态不是首屏最强视觉元素。

滚动时只允许照片产生 2% 至 4% 的慢速纵向位移，文字不持续漂浮。实现优先使用 CSS scroll-driven animation；兼容路径使用 `IntersectionObserver`，禁止 `window` 滚动监听。

`prefers-reduced-motion: reduce` 时取消裁切、视差和轨迹动画，只保留短暂透明度变化或完全静态显示。

## 6. 收尾页设计

### 6.1 布局

收尾区域位于长期定投专区之后，替换现有单行 footer。使用接近整屏的全幅摄影区域，推荐 `min-height: 88dvh`，在手机端不少于 `78dvh`。

城墙洞口照片作为完整背景，文案放在不遮挡宝宝面部的左上或中上安全区：

- 主标题：`把今天的认真，留给她的未来。`
- 说明：`每一笔记录，都是时间写给成长的答案。`
- 操作：`回到金库顶部`
- 底部署名：`送给最爱的宝贝`

文案不放在卡片中。使用浅色局部遮罩和深绿色文字，保持全站白绿主题，不切换为独立深色主题。

### 6.2 动效

- 当收尾区域进入视口时，照片进行非常缓慢的景深推进。
- 拱洞方向出现一条柔和的光线移动，强化“向前”的叙事。
- 主标题逐字或逐行显现，说明和按钮随后出现。
- 点击“回到金库顶部”使用原生平滑滚动；减少动态模式下使用即时跳转。
- 动画只播放一次，不循环闪烁，不影响页面滚动。

## 7. 响应式规则

### 7.1 桌面端

- 导航保持单行，高度不超过 72px。
- Hero 主标题最多两行，首屏内必须显示标题、副标题和两个操作按钮。
- 状态轨道必须完整显示在 Hero 底部，不覆盖人物。
- 收尾文案与人物保持清晰分区。

### 7.2 手机端

- Hero 使用 `100dvh` 稳定视口，不使用 `100vh`。
- 顶部导航只保留品牌和安装按钮，页面导航继续使用现有底部导航。
- 两个 Hero 操作按钮保持单行文字，可上下排列。
- 诊断信息为可横向滑动的紧凑轨道，不挤压标题。
- 收尾页保证宝宝全身主体不被底部导航遮挡，并增加安全区内边距。
- 所有文字不得覆盖宝宝面部。

## 8. 技术边界

本次采用现有 HTML、CSS 和原生 JavaScript 架构，不迁移 React，不引入新的运行时依赖。原因是本次只升级首尾品牌区域，而梦想金库主体已经拥有稳定的数据与交互逻辑。局部迁移 React 会增加状态同步和服务工作线程风险，收益不足。

计划新增：

- 一个独立的 Hero 与收尾页样式文件。
- 一个只负责入场与可见性动画的轻量脚本，或在现有脚本中增加隔离良好的初始化函数。
- 两张经过尺寸优化的本地图片资产及响应式变体。

不得修改：

- `data.json` 和 `backups/`。
- 行情 Worker、代理路由、缓存策略和 FX 逻辑。
- 交易、持仓、收益率和定投计算。
- GitHub 保存和管理员鉴权。
- 现有按钮 ID、状态 ID、锚点 ID 和公开函数名。

## 9. 性能与可访问性

- Hero 主图使用 WebP，并保留合适的 JPEG 或 PNG 回退。
- 主图设置明确宽高、`fetchpriority="high"` 和预加载，目标 LCP 小于 2.5 秒。
- 收尾图使用懒加载和异步解码。
- 图片遮罩必须保证正文达到 WCAG AA 对比度。
- 所有按钮保留键盘焦点样式和按下反馈。
- 导航和操作使用语义化元素，图片提供真实描述性 `alt`。
- 动画不引发布局偏移，目标 CLS 小于 0.1。
- Hero 图片加载失败时显示浅绿色静态背景，所有标题和功能仍可使用。

## 10. 验收标准

1. 打开页面首先看到全屏果园 Hero，而不是旧横向信息卡。
2. Hero 在 1920 x 1080、1440 x 900、390 x 844、360 x 800 下均不遮挡宝宝面部，标题和按钮不溢出。
3. 桌面导航能够跳转到五个现有模块，手机端底部导航继续正常工作。
4. 智能刷新、安装手机、版本、行情、美股时钟和账本状态继续使用原有函数与 ID。
5. 页面最下方出现城墙照片收尾页，能够返回顶部。
6. `prefers-reduced-motion` 下页面完整可用，且无持续动画。
7. 图片失败、离线、行情失败时，Hero 不出现空白或阻断主体页面。
8. `npm test` 与发布校验全部通过。
9. 浏览器控制台无新增错误，服务工作线程正常更新新增资源。
10. `data.json` 与所有账本备份文件保持不变。

## 11. 本次不做

- 不重新设计持仓地图、收益曲线、账本和定投专区。
- 不加入多图轮播、视频背景、音乐或自动播放声音。
- 不改变品牌名称和现有主要文案。
- 不增加股票分析、推荐或新数据接口。
- 不把整个网站迁移为 React 或 Vite。
- 不自动部署线上，完成本地视觉验证并经用户确认后再决定发布。
